# 技术骨架搭建迭代 PRD

## 1. 功能概述

本次迭代目标是为 Novel Factory 搭建一个可启动的后端基础工程，作为后续业务开发的统一技术骨架。

本次迭代包含以下功能点：

- 搭建基于 Spring Boot Web 的单体后端工程
- 使用 Gradle 作为构建工具，采用 Groovy DSL
- 按业务域规划代码目录和包结构，至少包括 `book`、`pipeline`、`agent` 和 `common`
- 提供 `book` 域的基础立项与管理能力骨架
- 提供一个最小可跑通的空流水线闭环：书籍接入后可创建一次流水线任务并返回任务状态
- 提供 `agent` 域的管理与编排骨架，为 `pipeline` 提供统一调用入口
- 接入 MySQL 与 MyBatis-Plus 的基础持久层配置
- 接入统一返回结构、全局异常处理、基础日志配置
- 接入 OpenAPI/Swagger 与 Actuator
- 提供基础 Dockerfile 和本地开发配置

## 2. Functional Requirements

### FR-001 工程基础骨架

- `FR-001` [P0] 系统应提供一个可直接启动运行的 Spring Boot Web 后端工程。
  输入：开发者执行标准启动命令。
  输出：应用启动成功，对外提供 HTTP 服务。
  异常处理：当配置缺失或启动失败时，应输出明确的启动失败信息，便于定位问题。

- `FR-002` [P0] 系统应使用 Gradle Groovy DSL 作为唯一构建方式。
  输入：开发者执行构建、测试或运行命令。
  输出：项目可通过 Gradle 完成依赖管理、构建和启动。
  异常处理：当依赖解析或构建失败时，应给出明确错误信息。

- `FR-003` [P0] 系统应规划清晰的代码目录和包结构，支持后续持续扩展。
  输入：开发者查看项目目录。
  输出：能明确识别应用入口、公共能力和各业务域边界。
  异常处理：无。

### FR-002 业务域划分

- `FR-004` [P0] 系统应按业务域组织代码，而非按 Agent 名称组织顶层结构。
  输入：开发者查看项目代码结构。
  输出：顶层至少体现 `book`、`pipeline`、`agent`、`common` 等业务域或支撑域。
  异常处理：无。

- `FR-005` [P0] `book` 域应承担书籍立项、基础管理和接入流水线的职责边界。
  输入：开发者查看 `book` 域代码结构与接口定义。
  输出：可识别书籍新增、查询和接入流水线等能力入口。
  异常处理：无。

- `FR-006` [P0] `pipeline` 域应承担创作流水线的任务创建、状态跟踪和流程承接职责。
  输入：开发者查看 `pipeline` 域结构与接口定义。
  输出：可识别流水线任务创建和任务状态返回等能力入口。
  异常处理：无。

- `FR-007` [P0] `agent` 域应承担 Agent 管理、编排和统一执行入口职责。
  输入：开发者查看 `agent` 域结构与接口定义。
  输出：可识别 Agent 注册、查询、状态管理或统一编排入口。
  异常处理：无。

### FR-003 Book 基础管理

- `FR-008` [P0] 系统应支持书籍立项的最小能力。
  输入：用户提交书籍基础信息。
  输出：系统返回立项结果，并生成可供后续管理的书籍记录。
  异常处理：当输入缺少必要字段或字段不合法时，应返回可理解的错误信息。

- `FR-009` [P0] 系统应支持书籍基础管理查询能力。
  输入：用户请求书籍列表或单本书详情。
  输出：系统返回书籍列表或详情信息。
  异常处理：当书籍不存在时，应返回明确的未找到提示。

- `FR-010` [P0] 系统应支持从书籍管理侧触发书籍接入流水线。
  输入：用户对某本书发起“接入流水线”操作。
  输出：系统返回接入结果，并进入流水线任务创建流程。
  异常处理：当书籍不存在、状态不允许接入或请求非法时，应返回明确错误信息。

### FR-004 最小空流水线闭环

- `FR-011` [P0] 系统应提供一个最小可跑通的空流水线闭环。
  输入：来自 `book` 域的接入请求。
  输出：系统创建一次流水线任务，并返回任务标识与初始状态。
  异常处理：当任务创建失败时，应返回明确失败原因。

- `FR-012` [P0] 系统应支持查询流水线任务状态。
  输入：用户或调用方提交任务标识。
  输出：系统返回当前任务状态。
  异常处理：当任务不存在时，应返回明确的未找到提示。

- `FR-013` [P1] 系统应为最小空流水线保留后续扩展点，以便后续接入真实创作流程。
  输入：开发者查看流水线相关代码。
  输出：可识别任务执行、阶段扩展和 Agent 调用的扩展入口。
  异常处理：无。

### FR-005 Agent 管理与编排骨架

- `FR-014` [P0] 系统应提供 Agent 管理骨架，支持基础信息维护或查询。
  输入：用户或开发者请求查看 Agent 定义或状态。
  输出：系统返回 Agent 基础信息或状态结果。
  异常处理：当 Agent 不存在时，应返回明确提示。

- `FR-015` [P0] 系统应提供供 `pipeline` 调用的统一 Agent 编排入口。
  输入：`pipeline` 发起一次占位执行请求。
  输出：系统返回占位执行结果或状态。
  异常处理：当调用参数不合法或执行失败时，应返回明确错误信息。

- `FR-016` [P1] 系统应使用占位执行逻辑模拟 Agent 执行，不实现真实 AI 生成能力。
  输入：流水线触发 Agent 执行。
  输出：系统返回预设或占位执行结果，证明调用链路可用。
  异常处理：当占位执行发生异常时，应返回明确失败信息。

### FR-006 基础工程能力

- `FR-017` [P0] 系统应提供统一返回结构，用于规范接口输出。
  输入：任意正常业务请求。
  输出：返回结构一致的成功响应体。
  异常处理：无。

- `FR-018` [P0] 系统应提供全局异常处理机制。
  输入：发生参数错误、资源不存在或系统异常的请求。
  输出：系统返回统一格式的错误响应。
  异常处理：异常本身应被统一接管，不向用户暴露无结构错误。

- `FR-019` [P0] 系统应提供基础日志配置。
  输入：应用启动、接口访问、异常发生等运行事件。
  输出：系统输出结构清晰、便于排查的日志信息。
  异常处理：无。

- `FR-020` [P0] 系统应接入 MySQL 与 MyBatis-Plus 的基础持久层配置。
  输入：应用启动和基础数据访问请求。
  输出：系统具备后续落地实体、Mapper、持久层服务的基础运行条件。
  异常处理：当数据库连接或配置异常时，应输出明确错误信息。

### FR-007 运行验证与文档能力

- `FR-021` [P0] 系统应提供用于验证工程可用性的基础接口或健康检查能力。
  输入：用户访问健康检查或骨架验证接口。
  输出：系统返回可用状态，证明工程正常运行。
  异常处理：当服务异常时，应返回对应失败状态。

- `FR-022` [P1] 系统应接入 OpenAPI/Swagger，供开发阶段查看接口文档。
  输入：用户访问接口文档入口。
  输出：系统展示当前暴露接口的文档信息。
  异常处理：当文档组件未正常加载时，应有可定位问题的日志信息。

- `FR-023` [P1] 系统应接入 Actuator，供开发阶段进行运行状态检查。
  输入：用户访问 Actuator 相关端点。
  输出：系统返回基础运行状态信息。
  异常处理：当端点不可用时，应有明确配置或访问反馈。

### FR-008 本地开发与部署骨架

- `FR-024` [P1] 系统应提供本地开发所需的基础配置。
  输入：开发者在本地运行项目。
  输出：可基于约定配置完成本地启动与调试。
  异常处理：当本地关键配置缺失时，应有明确提示。

- `FR-025` [P1] 系统应提供基础 Dockerfile，用于后续容器化部署扩展。
  输入：开发者查看或执行容器构建。
  输出：项目具备基础容器化入口。
  异常处理：当容器构建失败时，应可通过构建日志定位原因。

## 3. Non-Functional Requirements

- `NFR-001` 本次工程应基于 `Java 21`。
- `NFR-002` 本次工程应基于 `Spring Boot 3.x`。
- `NFR-003` 本次工程应使用 `Gradle Groovy DSL`。
- `NFR-004` 代码结构应具备明确的可扩展性，便于后续新增业务域、流水线阶段和 Agent 类型。
- `NFR-005` 所有对外接口响应格式应保持一致，便于前后端联调和后续统一治理。
- `NFR-006` 启动、调用失败和系统异常应具备基础可观测性，至少可通过日志快速定位问题。

## 4. 验收标准

- 工程可通过 Gradle 完成启动与基础构建。
- 项目存在清晰的按业务域划分的代码目录结构，至少覆盖 `book`、`pipeline`、`agent`、`common`。
- 应用启动后可通过健康检查或验证接口证明服务可用。
- 系统存在书籍立项与基础查询的最小能力入口。
- 系统存在从书籍接入流水线的能力入口。
- 系统存在最小空流水线任务创建与任务状态查询能力。
- 系统存在供流水线调用的 Agent 编排统一入口，且使用占位执行逻辑。
- 系统已接入 MySQL 与 MyBatis-Plus 基础配置。
- 系统已提供统一返回结构、全局异常处理和基础日志配置。
- 系统已接入 OpenAPI/Swagger 与 Actuator。
- 项目包含基础 Dockerfile 和本地开发配置。

## 5. Out of Scope

- 不实现具体业务规则和完整业务流程细节
- 不完成真实 AI 生成能力接入
- 不接入发布平台
- 不接入消息队列、调度中心等完整基础设施
- 不实现完整鉴权与登录体系
- 不完成完整数据库表设计和全量持久化业务闭环
- 不实现前端页面或前后端联调页面
