# Novel Factory 迭代 PRD

## 1. 功能概述

本次迭代目标是打通 Novel Factory 的第一条真实创作主链，并将其设计为后续完整产品蓝图的正式起点，而不是一次性的临时实现。

本次迭代聚焦“新书启动前半链路”的业务资产生产，覆盖以下能力：

- 录入书籍基础信息
- 为书籍创建一次创作流水线任务
- 通过统一 `AgentOrchestrator` 发起真实 LLM 调用
- 按未来 Agent 语义完成最小创作链路：
  - `F1 AddictionDesignerAgent` 语义对应的上瘾画布产物
  - `B1 WorldAgent` 语义对应的世界观设定产物
  - `B2 CharacterAgent` 语义对应的人物设定产物
  - `B3 OutlineAgent` 语义对应的大纲草案产物
- 生成并持久化策划卡，作为对前述中间产物的聚合型业务结果
- 查询任务状态与各类创作产物

本次迭代虽然采用同步执行方式，但必须保留任务状态流转语义，为后续异步执行、更多 Agent 串联、三层记忆接入和统一模型路由扩展留出兼容空间。

## 2. Functional Requirements

### FR-001 书籍基础信息管理（P0）

- 系统应支持创建书籍基础记录并持久化到数据库。
- 书籍基础信息至少包括：书名、题材、目标平台、简介/故事摘要、创建来源、当前生命周期状态。
- 系统应支持查询书籍列表。
- 系统应支持查询书籍详情。
- 当书籍不存在时，系统应返回明确错误码与错误信息。

### FR-002 创建创作流水线任务（P0）

- 系统应支持为某本书创建一条创作流水线任务。
- 本次任务以“新书启动前半链路”为目标，任务语义必须显式对齐未来 Agent 蓝图，而不是抽象成无含义的黑盒生成。
- 任务请求中应至少支持以下生成目标：
  - `PLAN_CARD`
  - `PLAN_CARD_AND_OUTLINE`
- 当生成目标为 `PLAN_CARD` 时，系统至少应完成：
  - 上瘾画布生成
  - 世界观设定生成
  - 人物设定生成
  - 策划卡生成
- 当生成目标为 `PLAN_CARD_AND_OUTLINE` 时，系统应在上述产物基础上继续生成大纲草案。
- 当书籍不存在时，系统应拒绝创建任务并返回明确错误信息。
- 本次任务执行采用同步执行语义：接口请求返回时，应给出任务最终结果或失败结果，而不是仅返回受理成功。

### FR-003 统一 Agent 调用与未来语义对齐（P0）

- 系统应通过统一的 `AgentOrchestrator` 发起真实模型调用，不得继续使用 stub 返回固定结果。
- 本次实现虽然不要求落地完整多 Agent 编排平台，但生成流程的职责定义必须对齐未来蓝图：
  - `F1 AddictionDesignerAgent` 负责定义上瘾画布
  - `B1 WorldAgent` 负责生成世界观设定
  - `B2 CharacterAgent` 负责生成主角/核心角色设定
  - `B3 OutlineAgent` 负责生成大纲草案
- 本次实现可以在一个统一编排入口内顺序调用上述能力，但不得把这些产物混成不可区分的单段自由文本。
- 系统应保留最小模型路由配置结构，允许通过配置指定默认模型、厂商、基础参数，并为后续 Agent 级路由扩展保留结构兼容性。
- 系统应保留 Prompt 模板配置入口，至少支持通过配置或模板文件调整本次创作链路所用 Prompt。
- 调用失败时，系统应记录失败原因，并将任务状态标记为 `FAILED`。

### FR-004 上瘾画布产物生成与查询（P0）

- 系统应基于书籍基础信息生成独立的上瘾画布产物，对齐 `F1 AddictionDesignerAgent` 的最小职责。
- 上瘾画布至少应包含：
  - 核心情绪钩子
  - 主要情绪燃料
  - 目标读者幻想
  - 压抑-爆发节律
  - 禁止破坏沉浸感/上瘾感的红线
- 生成成功后，系统应将上瘾画布作为独立业务产物持久化。
- 系统应支持按书籍查询最新上瘾画布。
- 当对应产物不存在时，系统应返回明确错误信息。

### FR-005 世界观设定产物生成与查询（P0）

- 系统应基于书籍基础信息和上瘾画布生成独立的世界观设定产物，对齐 `B1 WorldAgent` 的最小职责。
- 世界观设定至少应包含：
  - 作品定位
  - 世界观摘要
  - 核心规则/力量体系
  - 势力或关键关系结构
  - 禁止项清单
- 生成成功后，系统应将世界观设定作为独立业务产物持久化。
- 系统应支持按书籍查询最新世界观设定。
- 当对应产物不存在时，系统应返回明确错误信息。

### FR-006 人物设定产物生成与查询（P0）

- 系统应基于书籍基础信息、上瘾画布和世界观设定生成独立的人物设定产物，对齐 `B2 CharacterAgent` 的最小职责。
- 本次至少应生成：
  - 1 名主角
  - 2 至 3 名核心配角或关键关系角色
  - 1 名主要对立角色或关键冲突角色
- 每个人物至少应包含：
  - 角色名称
  - 角色定位
  - 背景
  - 核心动机
  - 性格特征
  - 角色成长或关系张力
- 生成成功后，系统应将人物设定作为独立业务产物持久化。
- 系统应支持按书籍查询最新人物设定集合。
- 当对应产物不存在时，系统应返回明确错误信息。

### FR-007 策划卡生成与查询（P0）

- 系统应基于书籍基础信息、上瘾画布、世界观设定和人物设定，生成结构化书籍策划卡。
- 策划卡是本次链路中的聚合型业务资产，不替代中间产物的独立存在。
- 策划卡至少应包含：
  - 书名
  - 题材
  - 目标平台
  - 一句话卖点
  - 核心设定
  - 目标读者
  - 核心冲突摘要
  - 创作方向摘要
- 生成成功后，系统应将策划卡持久化，并更新任务阶段状态。
- 系统应支持按书籍查询最新策划卡。
- 当对应产物不存在时，系统应返回明确错误信息。

### FR-008 大纲草案生成与查询（P0）

- 当任务目标为 `PLAN_CARD_AND_OUTLINE` 时，系统应在策划卡生成成功后继续生成大纲草案，对齐 `B3 OutlineAgent` 的最小职责。
- 大纲草案至少应包含：
  - 作品定位
  - 世界观摘要
  - 主角设定摘要
  - 主线冲突
  - 阶段剧情概览
  - 弧线级结构或阶段推进方案
- 大纲草案应明确依赖前序中间产物，而不是仅依赖书籍标题和简介直接生成。
- 生成成功后，系统应将大纲草案持久化，并更新任务阶段状态。
- 系统应支持按书籍查询最新大纲草案。
- 当对应产物不存在时，系统应返回明确错误信息。

### FR-009 任务状态流转与结果查询（P0）

- 系统应记录任务执行状态。
- 任务状态至少支持：
  - `CREATED`
  - `RUNNING`
  - `ADDICTION_CANVAS_DONE`
  - `WORLD_SETTING_DONE`
  - `CHARACTER_PROFILE_DONE`
  - `PLAN_CARD_DONE`
  - `OUTLINE_DONE`
  - `COMPLETED`
  - `FAILED`
- 当任务目标为 `PLAN_CARD` 时，系统在 `PLAN_CARD_DONE` 后应直接进入 `COMPLETED`。
- 当任务目标为 `PLAN_CARD_AND_OUTLINE` 时，系统应在 `PLAN_CARD_DONE` 后继续进入 `OUTLINE_DONE`，随后进入 `COMPLETED`。
- 任务失败时，应记录失败阶段、失败摘要和排查所需的最小上下文。
- 系统应支持根据任务 ID 查询任务状态。
- 查询结果中至少应包含：
  - 任务 ID
  - 书籍 ID
  - 生成目标
  - 当前状态
  - 失败信息或结果摘要
  - 已生成产物的引用信息

### FR-010 独立产物查询接口（P0）

- 系统应提供按书籍查询最新创作产物的只读接口，至少包括：
  - 最新上瘾画布
  - 最新世界观设定
  - 最新人物设定
  - 最新策划卡
  - 最新大纲草案
- 接口返回应支持区分“未生成”“生成失败”“存在历史版本但当前任务未产出”等不同语义，不得仅返回空字符串。
- 如产物不存在，应返回明确错误码与错误信息。

### FR-011 最小执行日志能力（P1）

- 系统应新增最小 `agent_execution_log` 能力，用于记录本次真实生成链路的关键执行信息。
- 每次任务执行至少应记录：
  - 任务 ID
  - 书籍 ID
  - 逻辑步骤/对应 Agent 语义
  - 使用的模型信息
  - 执行开始时间与结束时间
  - 成功/失败状态
  - 失败摘要
- 本次不要求复杂观测平台，但这些日志必须可用于后续排查真实调用问题。

### FR-012 三层记忆与统一路由的兼容约束（P1）

- 本次迭代不要求正式落地三层记忆系统，但产物设计应能够作为后续三层记忆的输入基础：
  - 上瘾画布、世界观设定、人物设定应可进入 Layer1 静态知识
  - 大纲草案应可作为后续章节脚本与 Layer2 汇总的输入来源
- 本次不要求实现完整 Agent 级模型路由，但配置结构不得阻断后续：
  - 系统级默认模型
  - 后续可扩展的 Agent 级覆盖
  - 基础 fallback 能力预留
- 本次不要求实现 RevisionRequest、投票机制、多版本生成，但相关字段或模型命名不应与后续蓝图冲突。

## 3. Non-Functional Requirements

- 本迭代继续使用 `Java 21`、`Spring Boot 3.x`、`Gradle Groovy DSL`。
- 同步执行模式下，单次任务的响应时长可以高于普通 CRUD 接口，但必须可观测、可失败、可追踪；如超时或调用失败，必须明确返回失败语义。
- 所有接口继续使用统一 `ApiResponse<T>` 返回。
- 所有失败场景必须返回明确错误码，不允许仅返回裸字符串错误。
- 模型调用配置必须支持通过环境变量或配置文件注入，敏感配置不得硬编码进代码仓库。
- Prompt 模板必须具备外部化能力，避免将关键创作提示词完全写死在业务代码中。
- 日志要求以“够用”为准，重点覆盖：
  - 任务创建
  - 任务开始执行
  - 每个逻辑生成阶段开始与结束
  - LLM 调用开始与结束
  - 失败阶段与失败原因
- 数据模型设计必须支持未来版本化扩展，避免把一次任务结果强耦合覆盖为单记录不可追溯状态。
- 本次不要求复杂审计能力、监控平台、异步任务框架和分布式调度能力。

## 4. 验收标准

- 能通过接口成功创建书籍并写入数据库。
- 能通过接口查询书籍列表与详情。
- 能为某本书创建一条 `PLAN_CARD` 任务，并同步完成：
  - 上瘾画布生成与保存
  - 世界观设定生成与保存
  - 人物设定生成与保存
  - 策划卡生成与保存
- 能为某本书创建一条 `PLAN_CARD_AND_OUTLINE` 任务，并在上述基础上继续生成并保存大纲草案。
- 任务状态能按阶段正确流转，并可查询。
- 能按书籍查询最新上瘾画布。
- 能按书籍查询最新世界观设定。
- 能按书籍查询最新人物设定。
- 能按书籍查询最新策划卡。
- 能按书籍查询最新大纲草案。
- 真实 Agent/LLM 调用链路已替换 stub。
- 至少存在最小 `agent_execution_log` 记录，用于定位某次任务的执行步骤与失败原因。
- 当 LLM 调用失败、生成结果解析失败或中间产物生成失败时，任务能标记为 `FAILED`，并保留失败阶段与失败原因。
- 测试覆盖至少包括：
  - Web/API 成功路径
  - 参数校验失败
  - 书籍不存在
  - `PLAN_CARD` 单产物路径
  - `PLAN_CARD_AND_OUTLINE` 完整路径
  - 中间产物查询成功路径
  - 中间产物不存在路径
  - LLM 调用失败
  - 中间某阶段失败导致任务失败

## 5. Out of Scope

- 完整多 Agent 协同编排平台
- 章节脚本生成、章节正文生成、章节审稿、发布流程
- 三层记忆系统的完整落地与自动维护
- Agent 级动态模型路由的完整实现
- 多版本生成与投票机制
- RevisionRequest 事件总线
- 异步消息队列、分布式任务框架、复杂重试平台
- 前端页面
- 人工审批流
- 权限、鉴权、审计
- 浏览器插件、平台自动发布、平台数据自动采集

## 6. 依赖说明

- 本次 PRD 的最终产品目标以上位文档 `novel_factory_prd.md` 和 `novel_factory_business_architecture.md` 为准。
- 本次迭代属于完整蓝图中的“新书启动前半链路最小落地”，核心对齐对象包括：
  - `F1 AddictionDesignerAgent`
  - `B1 WorldAgent`
  - `B2 CharacterAgent`
  - `B3 OutlineAgent`
- 本次产物将作为后续章节生成、大纲细化、三层记忆接入和发布链路的正式输入资产。
